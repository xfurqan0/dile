# Dile — project notes and v1 plan

Internal project notes. Kept in English so the repo is readable by everyone.

> **Dile: hold a key, speak, let go. Turkish-first local dictation.**
> Local, open-source, push-to-talk dictation. Windows first, macOS and Linux later from the same codebase. Audio never leaves the machine.
>
> Linux is a preview, and one respect makes it a different product: it hands a dictation over on the clipboard rather than pasting it. §9 is why.

- Repo: `github.com/xfurqan0/dile` · License: MIT
- Name: **Dile** (Turkish "dile getir", to put into words; "dil", language). Maintainer decision 2026-09-07.
- Siblings: [Nazar](https://github.com/xfurqan0/nazar) (agent canvas), [nazar-tray](https://github.com/xfurqan0/nazar-tray) (quota tray). Same stack (Rust + Tauri v2), same repo policy (English everywhere), same rule: **quality over schedule, no deadline; work packages are ordered, one finishes before the next starts.**
- Research phase closed 2026-09-07 04:15: market study (feature matrix of 8 apps, 12 pain-point clusters from issues, Rust/Tauri technical decisions, distribution) + engine study (Turkish ASR landscape, our own test material, filler statistics, M0 protocol). Internal notes hold the full reports (1,659 + 959 lines).
- Order: **third of the three projects to code** (maintainer decision 2026-09-07): **Nazar → nazar-tray → Dile**. nazar-tray is second because it produces the Tauri v2 / CI skeleton this repo copies in WP0; Dile is third because M0 needs a GPU machine and maintainer time.

## 1. Why it exists, corrected by the research

The first draft of this file said "no app ships the most accurate engine for Turkish". That is wrong, and the correction matters:

- **Handy already ships Qwen3-ASR (0.6B and 1.7B, GGUF, Apache-2.0) with Turkish in its language list**, next to Whisper and NVIDIA Nemotron 3.5 (Turkish supported). Its engine layer, `transcribe-cpp` (MIT, over `transcribe.cpp`, 16 model families, Vulkan/CUDA/Metal), runs Whisper *and* Qwen3-ASR behind one API. The engine is not the gap.
- **The numbers the first draft quoted were misattributed.** On the FLEURS subset that contains Turkish: Whisper large-v3 **6.85**, Qwen3-ASR-0.6B **10.37**, Qwen3-ASR-1.7B **6.62**. The "16.18" was the 0.6B model, not Whisper. Qwen's Turkish edge exists only at 1.7B and is thin.
- **Fine-tuning is where the accuracy is.** On 320 real Turkish clips, stock large-v3 WER **0.1213** → a 140-hour LoRA (`turkmedstt/whisper-large-v3-turkish-general`) **0.0792**, about 35 % relative. Free training data exists: `issai/Turkish_Speech_Corpus`, 218 h, MIT. On an independent Turkish benchmark (`ysdede/asr_benchmark_store`) `large-v3-turbo` scores **0.2014** vs large-v3 **0.1345**, and the most-downloaded "Turkish" fine-tune (`selimc/…turbo-turkish`) is a regression on 4/4 datasets despite its model-card claim. **Never trust a model card's WER; measure on our own set.**

**So what is the Turkish gap?** Care, not engines. Verified in Handy's source: the Turkish filler list is **empty** while 24 UI locales include Turkish; the dictionary's fuzzy matcher requires ASCII, so every word with `ç ğ ı ö ş ü` is silently dropped. OpenWhispr has no Turkish locale and closed both Turkish PRs unmerged.

**A direct Turkish-first competitor exists: [yusufipk/dikte](https://github.com/yusufipk/dikte)** (found by the maintainer 2026-09-07; audited the same night). Created 2026-07-25; 216 commits in six weeks; 148★, 15 contributors, 5 releases, 24 test files, CI on 3 Pythons × 2 OSes; **GPL-3.0**; Python 3.11 + PyQt6; Linux-first with macOS/Windows ports. It already ships two things this file wrongly claimed nobody had: a **Turkish hallucination-phrase filter** (16+ phrases, duration gate, diacritic-folded matching, `dikte/vad.py`) and a **free-text prompt that biases whisper.cpp and doubles as a glossary** (`config.py`, `api.py`). It also ships a CLI with `--json`, meeting recording with speaker split, file/SRT transcription, history, a live overlay, and **`dikte ask`: speech → a coding agent, with permission modes and session continuity**. Brief mode is not novel any more.

**Where dikte stops, measured against its own source:**
- Turkish cleanup is an **LLM prompt**, default provider **OpenRouter**: text leaves the machine by default; the local option needs llama.cpp and gigabytes of RAM. Its policy is "when in doubt, delete", which contradicts the maintainer's 230-cut edit log (*yani* 1.7–2.1/min and *aslında* 1.0–1.5/min are deliberately kept).
- **No push-to-talk** (toggle only); default hotkey `Ctrl+Space` (the IME conflict Dile rejected); default model `large-v3-turbo-q5_0` (0.2014 WER on Turkish vs 0.1345 for large-v3 in independent data); unsigned on Windows and macOS; Windows GPU path unfinished (open issue); no pre-roll; no locale-aware ı/İ casing; clipboard restore off by default.

**Dile's differentiation, restated after dikte:**
1. **Deterministic Turkish cleanup: no model, no network, no variance, keeps when in doubt.** Three strictness levels derived from real edit data. dikte cannot offer this without abandoning its architecture.
2. **The model is chosen by measurement on our own set, and the dictionary is what makes it accurate** (dikte defaults to the worst Turkish choice). v1 ships stock large-v3 `q5_0` with the dictionary prompt — no fine-tune, because none has earned the row yet. Dile's own LoRA later (WP8).
3. **Push-to-talk done right**: hold and toggle, pre-roll, first-word protection, sane default hotkey, clipboard restored by default, engine isolated, and a GPU path that actually works on Windows because a probe decides it rather than a guess.
4. **Rust/Tauri, signed, small**: one binary, no Python runtime, winget.
5. Brief mode stays on the roadmap as a **feature**, not a differentiator.

**Licence rule (hard):** dikte is GPL-3.0, Dile is MIT. **No code, no snippet, no data file is taken from dikte.** Ideas may be studied and reimplemented independently; every such case is noted in this file with the idea, not the code. Contributing Dile's rule engine to dikte is ruled out: it would hand the only differentiation to a copyleft project.

**Search reality:** "dikte" is the generic Turkish word for dictation, so dikte owns every natural query. Dile is not going to be found by searching for it: discovery is GitHub topics and word of mouth, and the README carries that weight.

## 2. Position and boundaries

| Dile **is** | Dile **is not** |
|---|---|
| Turkish-first local dictation that also works in English | The 20th general dictation app (Handy is that, and it is good) |
| Cleanup and dictionary built for an agglutinative language with diacritics | An English cleanup list with "tr" bolted on |
| Local engine; Vulkan by default behind a first-run probe, CPU as the fallback tier | Cloud STT (Win+H, the dictation built into browsers and chat assistants) |
| v2: brief mode for coding agents | A voice assistant or command runner |
| Audio and text never leave the machine; no telemetry | An account or subscription |
| Push-to-talk dictation into whatever text field has focus | **Meeting recording with speaker split · file/batch transcription · SRT or subtitle export.** Deliberately out of scope (decided 2026-09-07). dikte ships all three; staying narrow is a decision, not a forgotten gap — writing it here is what keeps it from drifting back in |

## 3. Decisions taken in the research phase

| Topic | Decision | Why |
|---|---|---|
| Engine runtime | **`transcribe-cpp`** (MIT) through its Rust crate is **the single decision runtime**: one runtime for Whisper, Qwen3-ASR and Nemotron; Vulkan/CUDA/Metal. **M0 is model-vs-model inside it, never runtime-vs-runtime.** Two consequences, both binding on M0: (a) a Turkish fine-tune that exists **only as CTranslate2** (e.g. `RsGoksel/RsGoksel_ITU_Mainframe`) may be measured from Python **for information only**, and its number cannot select the v1 model until the weights are converted to ggml/gguf and re-measured inside `transcribe-cpp`; (b) **an engine with no Rust path cannot win**, whatever its WER — every candidate row in the M0 table carries a "Rust path" column and an empty one is disqualifying. **`whisper-rs` is not a candidate:** its GitHub mirror is archived/stale, the live Codeberg repo has been quiet for ~6 months, and its two hottest code paths have open bugs (`set_initial_prompt` CString leak #280, VAD broken in `FullParams` #242). `ct2rs` is likewise out (Windows shutdown deadlock open since 2024). | Proven in Handy (31k★). Removes the Python question for Qwen3-ASR (the candle route does not build on Windows with current CUDA; the llama.cpp GGUF route is an unmerged fork). The "Rust path" rule exists because a runtime we cannot ship is a benchmark, not a decision. |
| Model candidates for M0 | Whisper large-v3 (baseline) · `turkmedstt/whisper-large-v3-turkish-general` · `RsGoksel/RsGoksel_ITU_Mainframe` (CV17-tr WER 8.73, MIT; ships as CTranslate2, needs conversion) · Qwen3-ASR-1.7B · Nemotron 3.5 ASR 0.6B (streaming, Turkish, 495 MB). **Excluded:** large-v3-turbo, `selimc/…turbo-turkish` and its three derivatives. | Independent benchmark data above. |
| Engine tiers and defaults | **Vulkan is the default tier and CPU is the fallback** (maintainer decision 2026-09-13, replacing the 09-07 "CPU default, GPU opt-in"). The tier is never assumed: on first start the app runs a **probe transcription inside the isolated engine process**, and only a device that returns a correct result is used. A probe that fails, hangs or takes the process down drops that machine to the **CPU fallback tier with a small model**. The tier stays visible and switchable in settings, and the engine stays in its own process on both tiers. CUDA is not shipped. | The M0 rows decided it, and they point the other way from the 09-07 plan. **Considered and rejected — CPU default:** no whisper model is usable on a six-core CPU (turbo is the fastest and still runs at RTF 2.3, plus ~10 s cold start; q5_0 is ~10 s per dictation), and the small models that *are* faster than real time (Qwen3-ASR-0.6B, RTF 0.27, p95 1.37 s) **cannot take an initial prompt at all** (`accepts_ext(Run,'WHRN') = false`), which removes the dictionary — the product's actual accuracy feature — and leaves WER ≈ 0.491 with 11/31 terms. A CPU-default product would ship the worst version of the thing Dile exists to fix. **Considered and rejected — GPU "Auto":** Handy #1755 (open) has a Vulkan auto-GPU path bug-checking an RTX 5090 (`UNEXPECTED_STORE_EXCEPTION`), and Handy defaults to Auto. A driver-level fault is not something a process boundary can contain, so the answer is a probe rather than a guess, and the toggle stays. Vulkan rather than CUDA on size and hardware: 53 MB against 627 MB, and the official whisper.cpp Windows CUDA builds (11.8 / 12.4) predate Blackwell's sm_120 (needs CUDA ≥ 12.8). **Implemented 2026-09-13 (WP3), and the probe is specified now rather than described:** a ~2 s Turkish clip, synthesised by Windows' own Turkish voice and compiled into the application (`crates/dile-app/assets/probe.wav`), is transcribed in the engine process; the device passes if it answers inside the timeout without taking that process down **and** the transcript holds at least half of the sentence's seven words, compared after Turkish lower-casing and **without folding diacritics** — a device that writes `guzel` for `güzel` has lost the thing this product exists to get right. The answer is written once per machine to `<app config>/engine.json` as `{tier, decided_at, probe_result}`, and `probe_result` is fields rather than a sentence — `passed`, `device`, `load_ms`, `probe_ms`, `words`, `expected_words`, `error` — so WP5's settings page can render it in the user's language. A host built without `gpu-vulkan` is recorded as exactly that, never as a driver that failed. |
| Engine IPC | **The engine is a separate process, and the two speak a length-prefixed binary protocol over stdio** (maintainer decision W3-B, 2026-09-13). One frame is `u32 LE length` + `u8 kind` + payload, where kind 1 is UTF-8 JSON and kind 2 is raw `f32le` 16 kHz mono samples. Four requests — `hello`, `load`, `transcribe`, `quit` — each with an `id` the answer carries back; `transcribe` is the one with a second frame behind it. Frames are capped at 64 MiB, a bad frame is an error response rather than a panic, and a closed stdin is exit 0. The definitions live in `dile-engine-proto`, which **both** sides depend on and **neither** owns, and which has no dependency on the runtime — so the application links the wire and never the native library. | Stdio rather than a socket or a named pipe: no port to collide, no permissions to get wrong, no listener for anything else on the machine to find, and the child dies with its parent by construction. Binary frames rather than newline-delimited JSON because a minute of dictation is 3.8 million samples, and base64 would be a megabyte of encoding per dictation for nothing. One shared crate rather than two hand-written codecs because a message one side sends and the other has never heard of is otherwise found at run time on a user's machine. |
| v1 model | **Stock Whisper large-v3 `q5_0` (GGUF) with the dictionary fed in as the initial prompt** (maintainer decision 2026-09-13). **No fine-tune ships in v1**, and the README says so. | Measured on the decision layer's 20-sentence set: with the prompt, WER **0.261** and **30/31** technical terms, against 0.379 and 17/31 without it, at p95 2.38 s on Vulkan. **Considered and rejected:** `large-v3-turbo` (0.348, 28/31 with the prompt) saves 1.3 s and is the one row whose Icelandic hallucination survived the prompt; `large-v3` F16 (0.273, the same 30/31) is three times the size, the slowest GPU row, and still loses to its own quantization; every Turkish fine-tune (the most-downloaded one is a regression on 4/4 independent datasets, and the one serious candidate ships as safetensors, which the decision runtime cannot load). These numbers are **final on the 20-sentence set and the robustness set**; the term-heavy slice — the material the decision rule actually names — is **still awaiting the Dilim B reference**, so the pick is settled as a product decision and the term-heavy column is not yet filled. See §4. |
| Hotkey | **Default: `Right Ctrl`, held on its own** (maintainer decision 2026-09-14, replacing the 09-09 decision of `Ctrl+Alt+Space`, which had itself replaced the 07 decision of `Right Ctrl`). **One trigger with two shapes:** a lone modifier key, written side first (`RightCtrl`, `LeftAlt`, …), or a chord (`Ctrl+Alt+Space`). The modifier-only key is not an *option* beside a chord any more — it **is** the default, and a chord is what a user changes it to. `Ctrl+Alt+Space` was the shipped default from 2026-09-09 until 2026-09-14 and is the chord a user is most likely to choose. Detected through `handy-keys` (not `rdev`). **Hold by default:** press → the panel opens and recording starts; release → recording stops. A press shorter than the press-length threshold (~250 ms) is treated as a tap and does nothing except open the panel idle, so an accidental tap never dictates. **Toggle mode is a setting** — tap starts, tap stops — **and it latches a chord only.** A lone modifier is hold-to-talk in both modes, because a recording latched to a key a hand rests on is a trap; for the same reason the panel's re-record button does nothing under a lone-modifier trigger in Toggle mode, there being no latch for it to break. **`Ctrl+Space` is excluded permanently** — the IME chord is swallowed before it reaches even a low-level hook, and dikte already uses it — and a chord with no modifier in it is refused, because a bare key as a global hotkey takes that key away from every application on the machine. Re-verified against IME in WP2. **A chord trigger is swallowed; a lone modifier never is** (WP2, 2026-09-13; carried onto the trigger itself 2026-09-15): the hook is installed in blocking mode with the chord in its set, because a `Ctrl+Alt+Space` that still reaches the focused window puts a space in the editor being dictated into. A lone modifier stays out of that set — swallowing a bare right Ctrl would take `Ctrl+C` away from the whole machine — so `Right Ctrl` + `C` still copies, and the recording the press started is **withdrawn** the moment another key joins the hold. | A hand can rest on the right Ctrl for a whole sentence, and a three-key chord tires it inside a minute: that is what the hand test of the 0.1.0 installer found, and why the key that §3 had only *recommended* for long dictation became the shipped default. `Ctrl+Alt+Space` stays the discoverable alternative — not an IME toggle, not a Windows-reserved chord, and bound by no mainstream editor. Before `tauri-plugin-global-shortcut` 2.3.2 the Windows "Released" event was a 50 ms poll that burned a core, which is why `handy-keys` stays. |
| Panel (review UI) | **Dile does not paste blind. Every dictation lands in a panel first.** Maintainer decision 2026-09-09. The panel is a Spotlight-sized floating strip (≈ 680 × 64 px, top-centre of the monitor that holds the focused window, position draggable and remembered), **grey theme**, `focusable: false` (`WS_EX_NOACTIVATE`) so the target window keeps focus; mouse clicks still reach the buttons, and Enter / Esc / Ctrl+C are read from the global hook while the panel is visible. **States:** *recording* — level meter that moves with the microphone RMS (the idiom desktop dictation panels use), elapsed time, the 60 s cap shown, ✗ cancels · *processing* — honest status with elapsed time, never a blank spinner · *result* — the cleaned text, editable in place (clicking into the text is the one action that gives the panel focus; the target `HWND` was captured before the panel opened and is restored before pasting), plus three actions: **✓ transfer** (Enter), **copy** (Ctrl+C; copies without pasting and deliberately does not run clipboard restore, the user asked for the clipboard), **✗ cancel** (Esc). **Default flow after release:** the result is shown and **auto-transferred after 2.5 s unless the user presses ✗ or starts editing**; the countdown is visible. Auto-transfer can be disabled in settings (then ✓ / Enter is required every time). The panel shows the **target application label** ("→ VS Code") so the paste destination is never a surprise, and a **strictness chip** (light / medium / strict) that re-runs cleanup instantly; "show raw" reveals the engine output. **Re-record** button in the result state. | Reviewing before pasting is the one interaction gap that neither Handy nor dikte covers, and in Turkish the ability to fix a mangled proper noun before it lands is worth more than the 2.5 s. Auto-transfer keeps fast dictation fast; the countdown keeps the review possible. Non-activating window: the target keeps focus, so `SetForegroundWindow` restrictions are never hit ([tao `window_state.rs`], market report §4.5). **Implemented 2026-09-13 (WP5b), and four things are worth writing down because they are not what the design assumed.** (1) `focusable: false` in `tauri.conf.json` *is* `WS_EX_NOACTIVATE` — `tao` sets exactly that bit for that flag — so no hand-written window style was needed; the bit is read back off the real window at start-up and logged, which is how it gets checked at all. (2) The window is **transparent with a 14 px gutter** around the card, because a 12 px radius and a shadow need somewhere to fall; 680 × 64 stays the measurement of the *card*, and the window around it is 708 wide. (3) **The clipboard restore is text only.** `CF_UNICODETEXT` comes back byte for byte; an image, a file list, rich text or a spreadsheet range on the clipboard before a dictation does **not** survive it, because the offer begins with `EmptyClipboard`. That is a v1 limit, written here rather than discovered. (4) The countdown is cancelled by ✗, by any edit, **and by resting the pointer on the text for 300 ms** — reading is what a person does with the pointer where they are reading, and a countdown that ignores it is a countdown that fires mid-sentence. A strictness pill **restarts** it rather than cancelling it: the user has just been handed a different sentence and gets the whole window to read it in. |
| VAD | Evaluate `earshot` (40 KB minGRU, zero deps) vs Silero ONNX in M0. | First-word cut and hallucination on silence are top pain points; VAD quality decides both. |
| Paste | Handy's `paste_tx/windows.rs` pattern (delayed clipboard render, restore previous clipboard), MIT with credit. macOS AX / Linux portals in v2. **Implemented 2026-09-13 (WP5b), independently rather than copied**, in `crates/dile-app/src/win32/clipboard.rs`: a hidden message-only window owns the clipboard, `SetClipboardData(CF_UNICODETEXT, NULL)` is the promise, and `WM_RENDERFORMAT` is the receipt that says the target actually took the text — after which the previous clipboard goes back. A target that never pastes times out after 2 s with a log line, and the clipboard is restored anyway. **`arboard` was evaluated and cannot do this**: its API sets clipboard *contents*, and delayed rendering is a promise with a live window behind it, so the best it could offer is `set_text` and a sleep — which is the fixed delay this row exists to avoid. **Two Win32 traps, both found by the Notepad test rather than by reading**: a delayed-render offer succeeds by returning *null*, so the last error has to be zeroed before the call or the wrapper reports whatever error an earlier call left behind; and `EmptyClipboard` sends `WM_DESTROYCLIPBOARD` to the previous owner *synchronously*, which from the second dictation onwards is this process — so the pending offer must be recorded **after** the empty, or it is installed and immediately forgotten. | Only battle-tested approach in the field; typing key-by-key (WhisperWriter) is slow and lossy. |

## 4. Our test material and what the data says

**Audio exists, the reference does not.** 15:16 of the maintainer's own recordings — term-heavy Turkish speech, held locally and never published. The only written material that goes with them was written *before* they were recorded, so it is a script rather than a corrected transcript of what was actually said, and there is no raw/corrected ASR pair anywhere. The reference gets built in M0 with an adjudication method (two engines transcribe, the maintainer only resolves disagreements: ~30–40 min instead of 60–75).

**Where the evidence lives.** Every run quoted in this file was scored in a **benchmark workspace outside this repository**, and that workspace is not published: it holds model weights, the maintainer's own recordings and third-party audio. Run identifiers such as `results/2026-09-09-m0-sentences` appear below so a run can be found again from the maintainer's side; they are not links a reader can open, and nothing in this file depends on opening one.

**Test material, two layers (revised 2026-09-09 — maintainer proposed a YouTube-subtitle set; adopted as a second layer, not a replacement):**

- **Decision layer — the maintainer's own voice and domain.** Shrunk to what only he can supply: the **term-heavy slice** (takes 2, 4, 8, 9; ≈ 5 min; 11.0 technical terms/min), reference built by adjudication (≈ 10–12 min of maintainer time), plus the **20-sentence command set** recorded for this purpose (≈ 10 min): technical terms (`cron`, `SSH`, `CUDA`, `Tauri`, `token`, `cache`), numbers, English-mixed sentences, filler-heavy sentences, punctuation-critical questions. The exact sentences are held with the benchmark material. The clean-monologue and fast-casual slices (takes 1, 3, 7, 10, 11, 12) stay available but are no longer required before the v1 model is chosen. **Only this layer can select the v1 model**, and the technical-term-recall column comes only from here.
- **Robustness layer — independent speakers, zero maintainer time.** 2–3 Turkish technology videos from YouTube with **creator-uploaded subtitles** (auto-generated captions are disqualifying: they are another ASR's output, so scoring against them is circular), single speaker, 30–45 min total. Human subtitles are edited, not verbatim (fillers dropped, sentences tidied), so both sides are normalized before scoring: casing, punctuation, the `eee` filler regex and the particle list of §4 removed → **normalized WER**, used for *ranking* only, never quoted as an absolute accuracy number. Audio and subtitles live in the benchmark workspace, never in this repository, never published. **Agreement rule:** if the model ranking in this layer matches the decision layer, confidence rises; if it differs, that is a finding written into this file, and the decision layer still decides.
  **Assembled 2026-09-09** (94 candidates screened, 13 with a manual `tr` track, 3 accepted; 44:52 total): two TEDx talks with named volunteer transcriber and reviewer (Cem Say on NLP, Merve Ayyüce Kızrak on deep learning; stage lapel mic) and one Kubernetes screencast (desk mic, English terms inside Turkish sentences). ## 5. Turkish cleanup rules (v1, revised)

- **Light:** remove "eee" and its lengthened forms — **the default filler regex is exactly `\b[Ee]{2,}\b` and nothing else** (decided 2026-09-07), with duration/position guards from the VAD; any other filler pattern is opt-in in settings, never on by default. Remove the 24 known hallucination phrases when they appear as a whole segment; fix leftover whitespace/comma at sentence start.
- **Medium (default):** + sentence-initial capitalization; + punctuation normalization (comma pile-ups, "?" after question particles *mı/mi/mu/mü* and question words); + dictionary spelling of proper nouns and English terms (non-ASCII safe).
- **Strict:** + collapse consecutive repeats except a reduplication whitelist — **repeat collapsing is a strict-only rule and never runs in medium** (decided 2026-09-07); + drop standalone "şey" before a pause ("bir şey" stays); + drop *ya / yani / hani* at clause edges.
- Diacritics are never stripped; the engine's Turkish output is normalized to proper `ı/İ` casing rules (Turkish `i` ↔ `İ`, `ı` ↔ `I`).

## 8. Log
- 2026-09-17 — **A three-second dictation stops paying for thirty seconds, and the price is a fork.** WP8-adjacent, and the last of the three things `docs/BUILDING.md` said stood between this machine and its target. Whisper's encoder is fixed at thirty seconds: the frontend pads any shorter buffer to 3000 mel frames and the encoder attends over all 1500 positions, so a three-second take and a thirty-second take cost the same — and that one encoder pass was measured at **80–93 % of the wall clock**. whisper.cpp has had the parameter that shortens it since 2022 (`audio_ctx`, `-ac`); `transcribe-cpp` 0.2.3 does not expose it, **0.2.3 is the newest published version**, and the patch that would add it was proposed upstream and **declined** (handy-computer/transcribe.cpp#149: *"I generally don't like adding ENV flags as they feel like a hack… I am okay with some latency penalty at the cost of correctness"*). That is a reasonable position for a general-purpose runtime and the wrong one for a push-to-talk box, where the latency *is* the product. **So the runtime is now a fork we carry**, in-tree at `vendor/transcribe-cpp/`, upstream 0.2.3 verbatim plus one field threaded from the C struct to the Rust wrapper; `vendor/transcribe-cpp/VENDOR.md` holds the provenance, the five-file diff and the re-vendoring procedure.
  - **What it bought, on the tier that ships** (Vulkan, `large-v3-q5_0`, engine host over its own wire, model loaded): a 3 s clip **3.88 s → 1.27 s**, a 2 s clip 3.64 s → 1.17 s, a 10 s clip 3.77 s → 1.49 s. **Both of the port's stated targets are met** — ≤ 1.5 s at three seconds and ≤ 4 s at ten — where before only the second was. A 30 s take is unchanged by construction, because at thirty seconds there is no padding to drop.
  - **The rule is the whole design, and it scales with the audio.** `dile_engine::audio_ctx_for` is a pure function of the sample count: `ceil(67 × seconds)`, floored at 512 and ceilinged at 1500. Sixty-seven and not the fifty that one second *occupies*, because fifty is measured to be inside the broken band; 512 and not lower, because the failure below the floor is not an error. Forced to `audio_ctx = 192` a three-second clip on this machine returned the sentence **four times over and took 40 s** — the shortened window puts the decoder in a repetition loop, which trips `compression_ratio_thold`, which starts the temperature fallback ladder, and the encoder's saving comes back multiplied. **A fixed value could not have shipped**; the whole knob had to be a function or nothing.
  - **Three floors, two of them in the C++.** The policy never asks for a window shorter than the audio; the library enforces it anyway, and rounds the window up to an even mel-frame count because the conv2 stem has stride 2. The reason the library keeps its own floor is that the failure is silent: a window shorter than the speech does not error, it returns a confident wrong transcript.

## 9. Linux (preview): what a dictation does there, and why it is not a paste

Windows is still what ships (§2). This is the product decision Linux forced, taken 2026-09-16
with D-WP-L3, and it is here rather than in `docs/BUILDING.md` because it is a decision about
what Dile *is* on that platform rather than a note about how it is built.

### The decision: clipboard-first

**A finished dictation goes on the clipboard and the card says so** — *copied — press Ctrl+V
to paste* — and nothing is pasted anywhere. `platform::DELIVERY` is that decision in one
constant, `Delivery::Clipboard` against Windows' `Delivery::Paste`, and both of the panel's
paths are ordinary code, compiled and tested on both platforms.

It is not a degraded paste. §3's paste row rests on a promise: the target window is captured
when the recording starts and checked again when the text is ready, and a window that has gone
takes the paste with it. **A Wayland client is never told which window has the focus** — a
deliberate part of the protocol rather than a gap in it — so on Linux that promise cannot be
made, and a paste would put a sentence into whatever happened to be in front. Synthesising
`Ctrl+V` is the easy half and is within reach already: the trigger asks for `/dev/uinput`
anyway, so the chord costs no permission that has not been asked for. **Aiming it is the half
that does not exist.** A smaller promise that is kept beats a larger one that is not.

### What that costs, in full

The five limits of the feasibility work of 2026-09-15, every one of them measured on GNOME
50.4 Wayland rather than read:

1. **The target application cannot be named.** No "→ VS Code" on the card, no `Ctrl+Shift+V`
   for the terminal family, and no "that window is gone, so I did not paste" guarantee.
2. **Under Wayland the panel opens in the middle of the screen on every trigger, and nothing
   remembers where it was dragged to. The position memory works on the X11 backend.**
   `xdg-shell` has no global coordinate space, and `zwlr_layer_shell_v1` — how a HUD is placed
   elsewhere — GNOME does not advertise at all, so nothing can ask for top-centre. **Dragging
   was never the broken half**: what loses the position is *closing* the card, because
   `gtk_widget_hide` sends `xdg_toplevel.destroy`, mutter answers a destroyed toplevel by
   destroying its window, and the replacement is placed from scratch — into the middle of the
   screen, because `center-new-windows` is on.
   - **Minimizing instead was tried, shipped for a day and taken back out**
     (`platform::closing`, 2026-09-17). Keeping the window alive is only half a round trip; the
     other half is the compositor agreeing to raise it, and mutter will not. With another
     application focused — the only state a trigger read off an evdev device can fire in, because
     the compositor never saw the key — the same `xdg_activation_v1.activate` gets a `configure`
     carrying *activated* on a **mapped** surface and **nothing at all** on a **minimized** one.
     The card stayed down and the next right Ctrl did nothing anyone could see. The token is why:
     with no input serial to prove itself with, GTK3 sends `set_serial(0, seat)` and a token
     ending `_TIME0`, and `gtk_window_present_with_time` does not help, because GDK3's Wayland
     backend never puts an X11-style timestamp on the wire.
   - **Staying mapped and merely invisible** would keep the place *and* raise — raising a mapped
     window does work — but it cannot be built here: GDK3 implements neither `set_opacity` nor
     `set_keep_above` on its Wayland backend (both exist for X11 and for Broadway, and neither is
     a protocol request), so a panel that is never unmapped is a panel that is never off screen.
   - **X11 keeps the memory**, and there the round trip is a number rather than an inference: a
     window moved to (417, 733) came back from hide-and-show at **(606, 570)**, the centre of
     that screen, and came back from minimize-and-present at **(417, 733)**. So the X11 backend
     minimizes, reopens where it was dragged to for as long as the application runs, and pays a
     minimized *Dile* in the switcher while a card is closed — `skipTaskbar` has no Wayland
     equivalent either. There is **no switch in the settings window** for this and there is not
     going to be one: it is the environment variable `GDK_BACKEND=x11`, it costs the sharpness
     of fractional scaling, and every clipboard measurement in §9 was taken under Wayland.
   - A **restart** starts the next card wherever the compositor likes on either backend, because
     no protocol on this desktop carries a window's place across the process that owned it.
   `xdg-session-management-v1` is the one that would, and GNOME 50 ships it under an unstable
   name behind a debug switch, for restoring a session rather than for showing a window again.
3. **The card cannot refuse the focus.** `focusable: false` has no Wayland equivalent, so the
   card takes the keyboard from whatever you were typing in. **And that is what makes the
   clipboard work**: a client may set the selection only while it holds the keyboard, so the
   flag Dile cannot have here is the one that lets the card hand a dictation over at all. The
   application logs both halves of that trade in one line at start-up.
4. **The trigger needs a permission.** One udev rule, and `docs/BUILDING.md` says exactly what
   it grants.
5. **The tray icon needs an extension on GNOME.** Without one the icon is registered
   successfully and appears nowhere, so the application asks the session bus and says so
   itself, once, in a notification.

Out of scope for a v1 there, by the same decision: automatic paste, the target label, the
terminal chord, clipboard restore — there is nothing to restore, because a copy the user asked
for is a copy they keep — and pixel-accurate placement.

### How the clipboard is reached, and why not through a crate

`gtk::Clipboard`, on the connection this process already holds. The alternative was
`tauri-plugin-clipboard-manager`, which is `arboard`: six more crates, and it reaches the
selection through **XWayland** rather than Wayland, so a session without it has no clipboard
and nothing says so. `arboard` also cannot do a delayed render, which is the mechanism §3's
paste row is built on and the reason it was turned down for Windows in the first place; GTK
can, which is what the package that builds the Linux paste will need. Naming `gtk`, `gdk`,
`gio` and `glib` in the manifest added **no crate at all** to the graph — Tauri's Linux
backend is GTK3, so all four were already compiled into the binary, and `Cargo.lock` gained
four lines and no package.

Two measurements decided the shape of the write, and both are written down in
`crates/dile-app/src/platform/linux.rs`:

* **An unfocused write silently does nothing.** `set_text` returns, logs nothing, and the
  selection never changes.
* **`wait_for_text` cannot be used to check it.** GDK answers a read from its own local owner
  without asking the compositor, so it returns the text that was thrown away. What does work
  is the compositor's `owner-change`: it arrives on a write that landed and never on one that
  did not. So the write is followed by a wait for it, and a dictation that could not be handed
  over leaves the card up with the text still in it and the countdown stopped — losing a
  dictation is the one outcome this application never accepts.

A third measurement is a promise to the user rather than a mechanism: **the selection belongs
to the connection, not to the window**, so hiding the card does not take the text back — but
it does not survive *Quit*, on a desktop with no clipboard manager running.

### The experimental auto-paste, and why it is a setting rather than the behaviour

D-WP-L4, 2026-09-16. **`Ctrl+V` can be pressed for you, and Dile will do it if you ask.**
`paste.auto` in `settings.json`, a switch in the settings window labelled *Experimental:
press Ctrl+V for me*, **off by default**, and the settings window does not draw it at all on
Windows — where a dictation is pasted into the window it was aimed at, an unaimed chord is
not an extra, it is a worse version of what is already there.

**Nothing above this heading changed.** The hand-over is still the clipboard, the card still
says *copied — press Ctrl+V to paste* when the switch is off, and `platform::DELIVERY` is
still `Delivery::Clipboard`. What the switch adds is a key press at **whatever holds the
keyboard at that moment**, which is a different and smaller thing than a paste:

* It is not aimed and cannot be. The limit at the top of this section is unchanged — a
  Wayland client is not told which window has the focus — so this is *press the chord and see*
  rather than *put this sentence in that window*. `platform::window::send_paste_chord`, which
  is the aimed one, still answers `false` on Linux and has a test that keeps it that way.
* **In a terminal it is not paste.** `Ctrl+V` in most terminal emulators is a literal-next or
  nothing at all, and the chord that pastes there is `Ctrl+Shift+V` — which Dile picks per
  application on Windows and cannot pick here, because picking it means knowing what the
  target is. A person who dictates into a terminal with this on gets a chord that does
  nothing, and the text is still on the clipboard for them to paste properly.
* It costs no new permission. `/dev/uinput` is what lets a key be *swallowed*, and the
  trigger has asked for it since D-WP-L1; the same rule that makes hold-to-talk work is the
  one that makes this work. A machine without it gets one line on the card saying which of
  the two reasons it was, and the dictation on the clipboard as usual.

**The order is the whole implementation**, and it is in `panel.rs`'s `hand_over`: the virtual
keyboard is opened first, because opening is what fails and a failure has to leave the card up
with a line on it; then the card is hidden, because the card holds the keyboard and a chord
sent while it is up would be typed into the card; then a fifth of a second passes, which is
the compositor handing the keyboard back to whatever had it and the one number here that is a
guess rather than a measurement — there is no event that says *somebody else has the focus
now*, for the same reason there is no way to name the target; then the chord goes out.

And it belongs to **transfer** rather than to copy. Copy means *put this where I can take it*;
transfer means *put this where I am typing*. A person who pressed Copy did not ask to have it
pasted anywhere.

### The window flags Wayland has no answer for

`tauri.linux.conf.json` restates the panel window without `alwaysOnTop`, `focusable`,
`skipTaskbar` and `shadow`. All four are silently ignored there — the first two have no
`xdg-shell` request, `focusable` is limit 3 above, and `shadow` is a Windows and macOS setting
— and a configuration file that asks for four things it will not get reads like a build that
does not know. `tauri.conf.json` is untouched, so Windows is byte for byte what it was.
